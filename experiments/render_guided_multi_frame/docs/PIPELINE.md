# 实验流程

## 两帧前端：提出与精修运动

`frontend/strict_two_frame.py` 读取两帧 RGB、预计算 IGEV 深度和左右目一致性置信度。`tracking/feature_tracks.py` 缓存逐帧 SuperPoint 特征，通过 LightGlue 匹配建立可延续的二维 track。

可选配置 `configs/kitti360_sequence_flow.yaml` 将对应计算替换为单向金字塔 LK，再在源点和实际亚像素终点采样 SuperPoint 描述子进行余弦校验。已有 track 的真实终点优先作为下一帧起点，不要求重新检测；反馈复用当前帧对光流缓存。该路径不执行反向光流，记录拒绝原因到 `tracks/flow_tracking.jsonl`，用 `max_tracks` 限制每帧轨迹数。粗描述子图随帧缓存释放，归档只保存稀疏目录和观察。默认仍为 LightGlue；真实匹配精度、目标覆盖和连续性需要分别评价。

`frontend/hybrid_motion.py` 从 essential、PnP 和三维刚体拟合提出运动。候选共同竞争匹配点，利用双向重投影误差和按深度噪声归一化的三维误差打分；新增运动需要独立支持和代价改善。重复运动在共同支持点上的像素、三维预测足够接近时合并。
当前共享配置还对未解释区域进行一次有预算的局部 PnP/刚体发现；沿用现有核心、三维一致性和收益检查，
不改写旧核心及运动，最多额外建立 2 个候选。

稀疏点对各运动的概率，通过最近四个匹配点传播给高斯，权重同时考虑三维距离、深度差、颜色差和测量可靠性。缺乏可靠附近支持的高斯初始化偏向参考运动。

启用 object 窗口时，这份局部运动归属概率保持不变，前端只精修运动。反馈补匹配可以支持或修复已有运动；帧对内部的 birth/split/merge/prune 被关闭，下一帧对仍会独立发现新的运动。

`joint.motion_pose_guard` 逐运动模型验收 pose 更新：固定本次优化前独占且满足 metric 检查的
核心，至少 6 个才执行检查。优化后必须保留至少 80% 的置信度加权支持，且这些相同点上的
加权截断代价增长不能超过 0.1，否则该模型退回本次优化前 pose。最终 loss、梯度、
q_anchor 与渲染均以实际采用的 pose 重新计算；不会因背景占据大多数像素而忽略小运动核心。
这属于同观测一致性检查，不代表物理匹配准确率。

## 跨帧身份与高斯对应

`tracking/object_state.py` 将局部运动通过持续 track 关联到全局 object ID，允许多个相容候选暂时关联同一身份。比较的是当前帧对的运动解释能力，历史运动变换不会直接复制到新时间段。
当前独立可靠核心若不能由背景解释，可在满足现有竞争、收益和支持比例后拒绝历史 O0 身份。
在同一帧对内，身份判断保留运动发现阶段的核心观测集合，按当前运动重新检查重投影与三维可靠性，
再对 track 去重。后续新吸入的背景点不会稀释这组独立证据；失效或删除的观测不再提供支持。
未实际替换或追加 warm 运动时保留发现阶段的核心标签；这组二维、三维观测不直接复制到下一帧对。

`tracking.motion_identity.geometric_identity_ledger` 另外保留最近一个帧对的前景几何身份线索：
只有具有足够独占且 metric 可靠核心的局部模型，其有效 track→object 才进入该账本。
下一帧对必须与上一帧对相邻，同一 track 也必须再次通过当前独占核心、metric 和有效测量检查，
才能补入身份投票与身份支持数。至少 3 条独立身份支持和原有背景运动拒绝规则仍执行；
同 ID 的旧账本轨迹即使初始发现时为 unknown，精修后成为当前独占 metric 核心，也可补充身份票；
候选运动的代价、收益和支持比例比较仍使用原发现核心集合，不把新增点混入该几何比较集合。
当前另一个明确前景身份的冲突、重复 track 的矛盾、unknown 或失效观测不会增加几何身份支持。
该账本不进入灰点 soft association，不覆盖 `track_objects`、窗口 posterior 或最终 Gaussian 标签。
它只保留最近帧对的新鲜证据，跳帧、缓存裁剪、候选退出或 retirement 时清理。

短、长序列都继承 `configs/kitti360_sequence.yaml`：流式缓存、生命周期和运动身份门控相同，
帧范围、窗口长度、窗口推进步数和帧号 stride 独立控制。改变序列长短不切换估计方法。

如果候选在可靠支持上显著优于旧 object 当前的代表运动，身份门控允许拒绝历史身份并提出新 object。新身份先是 provisional，可靠当前观测确认存在后才记录出生。O0 留给背景；missing/retired 根据实际处理图像中的当前观测更新。

`ownership/gaussian_object_backend.py` 为每个 object 选择有当前支持的运动。高斯通过可靠 track，或在可用运动下的双向唯一几何/颜色对应共享稳定 Gaussian ID；对应不依赖旧归属的 argmax。
前景运动的高度重拟合只使用对应候选的绑定支持；全体观测仍可参与评估。
后端先建立各对象的参考模型，再针对固定参考表同步选择，避免 object ID 的处理顺序改变竞争基准。
单帧正证据、稳定 GID 的重复证据和连通核心分别统计；优化前执行无核回退，
优化后重新检查核心的最终归属与连接，清除过期核心所保护的对象和断开碎片。

## 多帧窗口：优化高斯属于谁

`ownership/object_window.py` 默认保留 7 张图像、6 个帧对，每次推进 5 张采样图像。每个稳定 Gaussian ID 共享一份 object 概率，首次初始化只提供弱先验。新的观测代价与上一轮后验分别用于证据和热启动。

共享配置启用 `object_window.render.initialization: measurement`。凑窗期间仍保留已有 posterior，
完整窗口或最终尾窗开始渲染求解时，根据全部当前中心观测以及边界充分统计得到能量 `E`，
以 `softmax((prior_weight * log(first_prior) - E) / (temperature + prior_weight))` 提出初始归属。
`first_prior` 是首次建立该 Gaussian 时的固定先验，新 object 列按 `prior_floor` 补齐，
旧 posterior 不会变成第二份观测或新先验。中心观测缺失、不可比较的行回到固定先验的温度软化分布，
不能仅凭初值获得新的观测支持或确定标签；之后仍参与实际渲染更新。
这个分布是显式 CPU 中心能量基线的解析解，但在 GPU RGB-D 渲染目标中只是初始化 proposal：
GPU 使用配置中的渲染、KL、核心和空间损失，其权重与 CPU 基线不同。
旧配置未设置该选项时默认 `previous`，继续使用上次 posterior 热启动；
`render_optimization.initialization` 记录实际使用的模式。

`ownership/object_render_optimizer.py` 固定观测高斯的几何、颜色及各帧对的 object 运动，在有效前向、反向视图中联合渲染 RGB、深度和覆盖率，累积梯度后统一更新共享归属。高度与核心连通约束在 `ownership/object_*constraints.py` 中实现。

完整窗口和最终尾窗求解后，`ownership/final_connectivity.py` 使用同一共享 GID 图执行硬投影。
核心点必须满足最终标签与观测支持；一个对象至少需要 3 个最终有效核心位于同一分支。
多个有效分支按核心运动优势选择，不能以区域面积决定。只有同对象为 argmax、概率至少 0.35、
有当前观测并通过高度规则的点可桥接；背景、高度禁用点不能桥接。共享配置的
`bridge_require_cost_compatibility: false` 允许中间表面不再额外通过逐点中心运动代价兼容门，
避免车体颜色、反光或深度局部噪声切断表面。核心资格仍要求可靠运动代价、重复正证据和最终 owned 标签；
原始核心若已不兼容当前运动，也不能只凭高 posterior 充当路径端点。
旧配置默认 `true`，保留原逐点兼容门。无有效核心的对象及断开区域回到 O0，
概率转移后重复检查至稳定。收集窗口不执行这一步。最终投影报告独立于投影前的渲染损失。

为避免真实稀疏车体核心被中间表面的光度孔洞拆散，`core_evidence_links` 只处理原来因
碎片化而无核的对象。每条候选核心连接必须在某一个源相机的端点局部矩形（外扩 4 px）内，
沿原深度/距离门控的几何图验证路径长度不超过 4 m。连接组还需有一帧共同可见、直径不超过
64 px，并有至少 3 条独立、具有正运动证据的 track。共享 GID 可汇总不同源帧各自验证的边，
不混合相机坐标。连接仅属于对应 object，中间表面不因此得到前景标签。
最终投影把仍有至少 3 个有效 owned core 的已认证组作为结构连接；背景或 unknown 核心
不参与，少于 3 个仍清理。诊断单列 `structural_owned_core_groups`，不冒称可见像素完全连通。

共享配置还设置 `bridge_require_background_observation: false`：表面路径可使用该 object 自身
有效且可靠的低代价观测；背景模型投影因遮挡、出画或无效深度失败，不单独否决这条表面路径。
这个选项只在 `bridge_require_cost_compatibility: false` 的表面模式生效。核心仍必须具有与背景
同时可比较的重复正运动证据；最终桥接仍需同 object 为最大概率、概率至少 0.35、有合格
自身观测、满足高度并连接到实际拥有的有效核心。未观测、低可靠或自身代价失效点不能因此桥接。

`connectivity.initialization_conditioning: certified_core_winner` 仅对初始最大概率已属于有
有界几何认证核心组的前景行，剔除无核候选后重新归一化优化初值。背景赢家、无核赢家、
没有该认证组的对象沿用原回退；概率平票按最小object ID。它要求measurement初始化、
渲染和最终硬连通/无核回退同时开启，凑窗与旧previous模式不执行。首次先验、观测能量、
核心选择和最终至少3个owned核心的检查不变。它是为稀疏核心对象提供的初始化策略，
不意味着认证组能证明物体真实运动；报告单列选中行数和被剔除的初始概率质量。

LK专用配置启用 `object_window.region_completion`。`ownership/core_region_completion.py`
在每个源相机中，从本窗口已有可靠核心、且当前帧仍有正运动证据的点出发，沿深度/三维距离
合格的像素邻接图扩展；强颜色边界截断边，较弱颜色差增加路径代价。自身运动观测必须可靠、
代价低于阈值；明确优于自身的背景或其他object运动，以及其他object核心和高度排除区域均为屏障。
默认路径预算3m、核心空间跨度上限8m，防止扩展沿弱连接进入远处背景；这些限制只控制补全，
不删除原object。若当前帧没有有效的出向运动，允许用相邻上一段已验证运动的逆变换，
把当前高斯投向上一帧的真实RGB-D观测重新评分；复用同一RGB-D代价公式，必须重新通过
自身拟合、背景优势和可靠性检查，不复制历史归属，也不虚构到下一帧的运动。
候选不使用当前posterior；同帧重叠区域排除后重新检查核心可达性，
跨帧同一GID若被不同object提出则不提供补全目标。

可信区域通过加权负log归属概率参与实际logit优化，按帧内均值、同object有效帧均值、object均值
归一化，避免大区域淹没小物体。权重考虑测量可靠性、自身运动代价和路径距离。此项是空间先验，
不增加重复运动观测或可靠核心，不改变首次先验，不强制硬标签；最终可见支持、概率门和硬连通
检查仍执行。可信区域的优化初值最低设为0.1，避免从零概率在有限迭代内无法恢复；
这不是最终标签门槛。若此前只因一个无核候选是旧赢家而被强制O0，当前可靠核心连接和
真实RGB-D观测允许它重新竞争其他有核object；原无核候选列仍禁用，高度强制排除不释放。
经过入向验证的点只补入表面观测资格，不能因此变成可靠运动核心。
每个源帧的 `region_completion_gaussian_ids`、`region_completion_object_ids`、
`region_completion_weights` 保存候选区域，和最终归属分开；`render_optimization` 报告独立region损失。
默认LightGlue配置没有启用此项。出向、入向均无可验证运动或没有可靠核心的帧不扩展，缺少高斯/深度的位置
也不凭该约束生成新几何；出画生命周期是另一个问题。

窗口中心证据按可靠性排序，用前后缀和计算原两两代价，分块50000行，并跳过不可比较行
和已移除候选列。该实现与原二次循环的目标相同，浮点求和顺序不同；旧实现仅保留在测试
参考中。真实片段的该CPU函数加速约1.28–2.32倍，不能外推为整条pipeline加速倍数。

可靠核的默认门仍为至少两个不同帧对的正观测（无 track 的点要求更多），单次 object 代价低于 0.5、
相对 O0 优势至少 0.3、测量权重至少 0.15，并通过支持比例、高度和至少 3 个核心的连通组检查。
`connectivity.seed_normalization: objects` 只调整渲染求解中的核心损失归一化：先平均每个 object 的
`-target * log(p)`，再对有核 object 平均，避免其它对象的大量核心稀释小对象的正梯度。
它不补造核心、降低门槛或改变中间像素的最终标签。

窗口优化能够修改早期帧的高斯/track 归属；每次更新会重写所有活动帧对的 `object_state.npz`。帧对离窗后封存，相关大数组释放，稳定 ID 不复用。原局部 `q_motion_initial` 保持独立，不被窗口结果覆盖。
归档中的 `evidence_H_object` / `evidence_object_model_valid` 保持与 `evidence_object_ids`、原始初始化和观测代价相同的列顺序；最终 `H_object` 继续对应保留的 `object_ids`。被清理候选的运动可用于独立重放。

整窗或最终部分窗口求解后，没有任何最终归属高斯的前景 object 从活动概率列及 registry 候选池移除。
其剩余软概率转入 O0，未知标签不因此升级为背景标签；凑窗期间保留临时候选。
原始候选证据和首次初始化保留原列编号，后续渲染、连通约束和中心代价跳过已移除 ID。
最终结果的 `objects` 仅包含在保存帧对中有归属高斯的 ID，空记录移入 `discarded_objects` 供生命周期审计。

关闭渲染优化时，CPU 基线只求解测量代价与先验、熵项；需要显式选择，不会在缺少 CUDA 时自动降级。

## 持久地图：优化高斯本身

启用 `gaussian_map` 后，`mapping/` 将可靠观测融合到持久地图。背景存世界坐标，动态 object 存各自规范坐标。先同步可靠归属修正，再固定本轮归属及相机/object 位姿，优化位置、RGB、三轴尺度、四元数和不透明度。

地图与观测使用不同的高斯 ID。地图参数和逐点 Adam 状态跨窗口保存，图像梯度与可靠可见证据驱动受限 split/clone/prune。子图按固定图像数量封存完整地图，只携带有界锚点和全局身份、位姿进入下一子图。

参数、文件格式和预算见 [地图说明](JOINT_GAUSSIAN_MAP.md) 与 [子图说明](SUBMAPS.md)。

## 工具与输出

`tools/visualization/` 读取保存状态绘图；`tools/validation/` 检查保存状态一致性。`tools/replay_object_window.py` 可重放短序列的固定观测和运动，用于归属求解对照；它仍拒绝流式输入，不重建长序列生命周期。

实验没有使用物体真值 mask 参与估计。渲染误差下降、概率增大或保存状态检查通过，分别说明目标改善、模型更确信或实现状态一致，不能直接等同于真实物体分割正确。当前尚未实现完整序列断点续跑、长遮挡重识别、回环和全局位姿联合优化。

渲染窗口默认按同一最终连通目标验收末次更新；总目标恶化时恢复受硬约束的热启动。该验收只约束优化目标，不保证分割正确。
最终连通硬投影随后执行，不宣称它降低了上述优化目标。
